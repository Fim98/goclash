# 12: 出口 IP 与 ASN

**What to build:** 填上首页 IP 卡里一直空着的出口信息。查询必须经内核的混合端口发出——直连查到的会是本机地址，那是代理客户端最不该展示的东西。

**Blocked by:** 09 (真实网关), 10 (系统代理)

**Status:** done

- [x] `internal/exitip`：一个客户端、两种响应格式。JSON 端点（`api.ip.sb/geoip` 这类）取 `ip` / `country_code` / `asn` / `asn_organization`；Cloudflare 的 `cdn-cgi/trace` 取 `ip=` / `loc=`。ASN 接受 `3462`、`"3462"`、`"AS3462"` 三种写法
- [x] 请求经 `http://127.0.0.1:<mixedPort>` 发出（HTTPS 走 CONNECT），8s 超时，响应限 64KB；失败返回 error 由调用方吞掉
- [x] 网关缓存结果：`Status()` 只读缓存，绝不在页面加载时等第三方请求；`RefreshExitIP()` 供卡片刷新按钮手动重查
- [x] 刷新策略：成功 5 分钟一次，失败 30 秒重试（启动时内核往往还在起，等 5 分钟会像坏了）；系统代理关闭或端点为空时直接清空缓存、不发请求
- [x] 切换节点、开关系统代理时**同步清空缓存**再异步重查——宁可短暂显示「—」，也不显示上一个地区的 IP
- [x] 地区码映射成中文名（HK 中国香港 / TW 中国台湾 / MO 中国澳门 / JP 日本…），未收录的码原样显示
- [x] 首页：刷新按钮改调 `refreshExitIP`；ASN 行有值才渲染；**原生 IP 徽章只在接口明确返回该标记时出现**，不再用「中转 IP」代替未知
- [x] 测试：exitip 8 条（两种格式、ASN 变体、无 IP 拒绝、HTTP 失败、空端点、label 回退）+ 网关 7 条（缓存进 Status、代理关闭清空、空端点跳过、手动刷新、失败降级、切换节点失效、地区映射）+ 前端 3 条（刷新按钮、隐藏原生徽章、无数据文案）

## Comments

- **端点选择**：默认 `https://api.ip.sb/geoip`。选它的唯一理由是**它返回 ASN**——`cdn-cgi/trace` 只有 IP 和国家，凑不出设计稿里那行 `AS4760 CLOUDFLARE`。代价是把出口 IP 告诉第三方；出口 IP 本来就是全世界都能看到的地址，但如果不想付这个代价，把 `settings.json` 的 `exitIPEndpoint` 改成 Cloudflare trace（只丢 IP + 国家）或留空（彻底关闭）都能工作。
- **为什么必须经代理**：`http.Transport{Proxy: ...}` 指向混合端口，mihomo 按规则转发。直连查询会把「本机宽带 IP」当成出口 IP 显示，比不显示更糟。
- **为什么缓存**：`Status()` 在每次页面挂载、每次刷新都会调用；把网络请求塞进去会让首页启动被第三方服务拖住。
- **不做原生 IP 推断**：要判断「原生」得知道 IP 注册地与节点所在地是否一致，我们两个都不知道。只有接口明确给 `is_native` 才显示，其余一律不显示——「中转 IP」是一个我们无法验证的断言。
- **无数据时**：IP 显示「—」，ASN 行显示「出口地区未获取」，地区徽章隐藏；卡片高度由 `mt-auto` 撑着，不会跳。
- **验证边界**：端点响应结构用真实 `curl` 抓的样本固化成测试；代理链路只用 `httptest` 验证了「按给定代理地址发请求」，本机没有 mihomo，真实内核下的端到端仍未跑过。
