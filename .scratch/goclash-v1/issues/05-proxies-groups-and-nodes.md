# 05: 代理页（策略组与节点）

**What to build:** 用户在这里完成日常最高频的动作：挑一个策略组、点一个节点、看延迟对不对。策略组以卡片形式纵向排列，组内节点两列平铺，选中态一眼可辨；右侧固定一列，随时告诉用户「现在走哪、订阅还剩多少」。

- [x] 节点网格两列（46px 高、3px 描边），名称 + 延迟徽章；<60ms 薄荷 / 60–150ms 阳光 / >150ms 蜜桃

## Comments

- **搜索与「全部测速」在页面头部**（portal 动作槽），工具条留给代理模式分段与排序——按 02 画板的位置，而不是票里「顶部工具条」的字面罗列。搜索框状态在页面内。
- **「最近命中」卡保留了**：画板里组卡下方还有一张三格规则卡（票里没写）。它补满左列、也确实是用户会瞄一眼的信息（命中次数前三的规则），用 `rules()` 现成数据，只读。
- **组卡去掉了画板里的装饰页脚**（「手动选择出口节点 · 最近测速 2 分钟前」）：两张组卡 + 最近命中卡比 644px 可用高度多出 24px，首屏会把最后一张卡截掉一截——宁可少一行装饰，不留半张卡。
- **右栏卡高从 158/184/158/96 收到 152/176/152/92**：原尺寸合计 656，比内容区 644 多 12px，链式卡会吃掉底部内边距。收 6px 肉眼看不出，但布局回到正确边界内。
- **契约增补 `Settings.chainedProxy`**（链式代理开关）；**mock 的 `select()` 会同步 `status.exitNode/exitLatency`**——只有主组（proxy）的切换才算改变出口，这样首页 Hero 与「当前出口」卡会跟着选中节点变。
- **mock 测速有真实耗时**（组 600ms / 全部 700ms）并每次把各节点延迟 -3ms（下限 20），让「测速中禁用 + 结束后延迟变化」可以真的被看到；不用随机数，测试不受影响。
- 链式代理开关默认关（白底黑滑块），与全站 Switch 一致；开状态薄荷。
- 延迟徽章在选中节点上强制白底黑字——珊瑚底上再叠薄荷/阳光会花，画板也是这么处理的。
