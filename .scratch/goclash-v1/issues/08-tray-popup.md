# 08: 托盘浮窗（420×620）

**What to build:** 常驻菜单栏的 420×620 浮窗（画板 03）：一眼看通断、一键切模式与节点、随时打开主界面。主窗关闭后应用留在菜单栏，退出走托盘菜单。

**Blocked by:** 02 (应用外壳), 03 (视觉原语), 04 (状态流)

**Status:** done

- [x] 第二个 Wails 窗口：420×620、无边框、置顶、不可缩放、初始隐藏，与主窗共用同一份前端产物（`/?window=tray`）
- [x] 菜单栏图标（模板图，浅/深色自动反色）+ tooltip；点击开合浮窗，Wails 负责贴图标定位（6px 间距）并在失焦时自动收起
- [x] 托盘右键菜单：打开主界面 / 退出 GoClash
- [x] 浮窗 UI：标题栏（珊瑚方点 + GoClash + 关闭）、状态 Hero（-1°、6px 薄荷影、64×34 中号开关，断开回白底）、规则/全局/直连分段、`节点 · 策略组` 标签行、延迟最低的 4 个节点（选中阳光填充）、上下行两个流量框、底部「打开主界面」
- [x] 关闭按钮与「打开主界面」通过 Wails 事件交给宿主：`tray:hide` 收起浮窗，`tray:open-main` 收起浮窗并 Show+Focus 主窗
- [x] 浮窗独立订阅流量流、独立读取状态与策略组；切换代理/模式/节点后立即回读
- [x] 测试：状态与四个最低延迟节点（SG/LA 不出现）；点节点走 `select("proxy", …)` 且 Hero 出口跟随；关闭系统代理后 Hero 变「未连接」；两个宿主事件被正确 emit（54 条全绿）

## Comments

- **只保留一个关闭按钮**：画板标题栏是「最小化 + 关闭」，但托盘浮窗的「最小化」没有语义（窗口本来就是点击开合、失焦自动收起），两个按钮同一行为比一个按钮更糟。
- **选中节点用阳光填充**（画板 03），与代理页的珊瑚选中态不同——两处画板本来就不同，按各自的稿做，不强行统一。
- **每个窗口各自实例化 mock 网关**：两个 webview 是独立 JS 上下文，浮窗里切系统代理不会同步主窗，这是 mock 阶段的固有限制；真实内核接进 Go 侧后由后端状态作为唯一真源。组件注释里写明了。
- **托盘图标是程序生成的 44×44 模板 PNG**（方框造型，对齐 4px 描边语言），先用占位；有正式品牌图标后替换 `build/trayicon.png` 即可。
- **应用退出策略**：`ApplicationShouldTerminateAfterLastWindowClosed` 保持 true，但隐藏的托盘窗口始终存在，因此关主窗不会退出应用；退出只能走托盘菜单——这是托盘应用的常规行为，已写进 main.go 注释。
- **验证方法**：无头 Chrome 有约 500px 的最小窗口宽度，直接 `--window-size=420` 截出来会被裁右侧（误报）。改为把 body 固定成 420×620 居中渲染后再截图，确认真实窄版无裁切。
- 开发态 `wails3 dev` 会同时创建两个窗口；浮窗默认隐藏，点菜单栏图标才出现。
