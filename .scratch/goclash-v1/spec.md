# GoClash v1 — 前端落地

Status: ready-for-agent
Feature slug: `goclash-v1`

## Problem Statement

内核已经能跑，但用户手上没有界面：仓库里只有一个 Wails 示例页（输入名字打招呼 + 每秒时间），既看不到连接状态，也管不了节点。团队已经把视觉定成「俏皮野兽派」并出了十张画板，但那些画板是静态 HTML/图片，没有任何一条真实交互被验证过——切换代理模式、选节点、关连接、看日志，目前全都停留在设计稿里。

对用户来说，问题很具体：**我打开这个应用，能不能一眼知道现在通不通、走的哪个节点、流量去了哪，并且能在两次点击内切到我想要的节点。**

## Solution

把七个页面（首页、代理、订阅、连接、规则、日志、设置）的前端一次落地，视觉严格对齐设计稿，数据来自一层可替换的网关接口——v1 用内存 mock 喂数据，等内核接入时只换实现、不动界面。

落地完成后：应用以 1440×900 打开，左侧七项导航可切换，首页显示连接状态与实时流量，代理页能选节点并看到延迟，连接/规则/日志三张表可筛选，订阅与设置可改，每页都有空、加载、错误三种面孔。

## User Stories

1. 作为刚装好 GoClash 的用户，我想在首页一眼看到「已连接/未连接」，以便判断现在是否需要动手。
2. 作为用户，我想在首页看到当前节点名、延迟和出口 IP，以便确认自己有没有走对线路。
3. 作为用户，我想在首页看到实时上下行速度，以便判断当前线路够不够用。
4. 作为用户，我想在首页看到最近的流量曲线，以便判断流量是否稳定、有没有突发。
5. 作为用户，我想在首页一键开关系统代理，以便快速断开而不必退出应用。
6. 作为用户，我想在首页切换规则/全局/直连，以便临时绕过分流。
7. 作为用户，我想看到内核是否在运行、混合端口是多少，以便排查「连不上」这类问题。
8. 作为用户，我想在代理页看到所有策略组，以便知道有哪些线路可选。
9. 作为用户，我想在策略组里点选节点，并且立刻看到选中态，以便确认切换成功。
10. 作为用户，我想看到每个节点的延迟，并按颜色区分快慢，以便挑一个快的。
11. 作为用户，我想对单个策略组或全部组测速，以便拿到最新的延迟。
12. 作为用户，我想按名称搜索节点，以便在 128 个节点里快速定位。
13. 作为用户，我想看到当前出口的卡片，以便无论滚到哪里都知道现在走哪。
14. 作为用户，我想看到订阅用量还剩多少、什么时候到期，以便判断要不要续费。
15. 作为用户，我想单独更新某个提供者，以便只刷新一部分节点。
16. 作为用户，我想看到链式代理开关及其代价提示，以便避免误开导致变慢。
17. 作为用户，我想在连接页看到当前所有连接及其命中规则，以便知道哪个应用在偷跑流量。
18. 作为用户，我想关掉单条连接或全部连接，以便中断可疑流量。
19. 作为用户，我想按代理/直连/拦截筛选连接，以便只看某一类。
20. 作为用户，我想关闭自动刷新，以便在排查时让列表停住。
21. 作为用户，我想在规则页看到规则的匹配顺序和命中次数，以便知道哪条规则在生效。
22. 作为用户，我想按规则类型筛选，以便找到某条域名规则。
23. 作为用户，我想看到兜底规则被单独标出，以便知道未命中时会发生什么。
24. 作为用户，我想在日志页按等级过滤，以便只看警告和错误。
25. 作为用户，我想日志自动滚动但可以关掉，以便停下来读某一行。
26. 作为用户，我想清空日志或直接打开日志目录，以便交给别人排查。
27. 作为用户，我想在订阅页导入新订阅、看到已有订阅的用量与到期，以便管理来源。
28. 作为用户，我想编辑本地配置补丁，以便让我的覆写不被订阅更新冲掉。
29. 作为用户，我想设置自动更新间隔与「更新后自动切最低延迟」，以便不用手动维护。
30. 作为用户，我想在设置页开关系统代理、TUN、开机自启，以便按自己的习惯使用。
31. 作为用户，我想看到内核版本并能检查更新，以便判断是否需要升级。
32. 作为用户，我想在没有订阅时被明确告知去导入，而不是看到一张空表。
33. 作为用户，我想在数据加载中看到骨架而不是白屏，以便知道应用没死。
34. 作为用户，我想在内核崩了时看到原因和「重启内核」按钮，以便自救。
35. 作为用户，我想在需要 TUN 权限时被说明清楚并一键安装服务，以便不卡在权限上。
36. 作为只用键盘的用户，我想用 Tab 走到每个控件并用空格切换开关，以便不依赖鼠标。
37. 作为对动效敏感的用户，我想在系统开启「减少动态效果」时不出现位移和旋转，以便不眩晕。

## Implementation Decisions

### 范围

v1 只做前端：全部页面可交互、可验证，数据来自网关接口的 mock 实现。真实内核接入（mihomo REST/WS、系统代理、TUN、服务安装）不在本期，但接口形状必须为它留好位置。

### 模块

- **shell**：窗口外壳，含标题栏、侧栏导航、页面切换与页面容器。
- **gateway**：数据网关接口 + 内存 mock 实现 + 订阅式数据流（traffic/log）。界面只依赖接口。
- **primitives**：视觉原语（按钮、卡片、标签、开关、分段、表格、状态面板等），不含业务。
- **pages**：七个页面，只组合 primitives + gateway。
- **format**：纯函数（字节数、速率、延迟分级、时长、时间戳）。

### 网关契约

界面与内核之间只有一个契约。传输入口用订阅函数而不是 Promise 轮询，这样以后换成 Wails Event 不需要改页面。

```ts
type Gateway = {
  status(): Promise<Status>;                    // 连接、代理模式、混合端口、TUN、内核版本
  groups(): Promise<Group[]>;                   // 策略组 + 节点 + 延迟
  select(group: GroupId, node: NodeName): Promise<void>;
  testGroup(group: GroupId): Promise<void>;
  setMode(mode: "rule" | "global" | "direct"): Promise<void>;
  setSystemProxy(on: boolean): Promise<void>;
  connections(): Promise<Connection[]>;
  closeConnection(id: ConnectionId): Promise<void>;
  closeAllConnections(): Promise<void>;
  rules(): Promise<Rule[]>;
  profiles(): Promise<Profile[]>;
  settings(): Promise<Settings>;
  updateSettings(patch: Partial<Settings>): Promise<void>;
  subscribe(stream: "traffic" | "log", onEvent: (e: TrafficSample | LogLine) => void): () => void;
};
```

`subscribe` 返回取消函数；页面卸载必须调用它，否则切页后 mock 仍在推数据。

### 决策

- **不自建路由**：桌面应用没有地址栏，页面切换是一个 `PageId` 联合类型 + 状态机，不引入 router 依赖。将来若需要深链接再替换，替换点在 shell 一处。
- **保留 shadcn/ui 但自建视觉层**：shadcn 只作为行为原语（Dialog/Tooltip 等后续按需引入）的来源与 `cn()` 的提供者；按钮、卡片、标签、开关、分段、表格全部自写。理由：这套风格的圆角、阴影、ring 语义与 shadcn 默认 token 相反，硬套会出现「一半圆角一半不圆角」。同时把 shadcn 的 CSS 变量覆盖到同一套色板（`--primary` = 珊瑚、`--ring` = 墨黑、`--radius` = 0），保证以后引入任何 shadcn 组件都自动落在风格内。
- **字体**：拉丁用 Inter（700/900），中文走系统栈（PingFang SC / Microsoft YaHei / Noto Sans SC）。不引入 CJK 字体包，避免几 MB 的子集下载。设计稿的「全站唯一字体」在中文语境下按此实现。
- **窗口**：1440×900，白底。macOS 保留系统原生 inset 红绿灯，**不渲染设计稿里那三颗假点**（否则会出现两组按钮）。标题栏高度对齐原生红绿灯的视觉中线。
- **动效**：统一 300ms `cubic-bezier(.34,1.56,.64,1)`；`prefers-reduced-motion: reduce` 时去掉位移与旋转，只保留颜色变化。
- **数据节奏**：traffic 1Hz 推送、日志环形缓冲 512 条、连接表最多 1s 刷新一次（避免表格抖动）。三个数值都写在 gateway mock 里，方便调。
- **表格是一等公民**：连接、规则、日志三页共用同一个表格原语（黑表头 46px、行 59/53px、页脚 56px），三页只在列定义与行内容上不同。
- **状态是页面的一部分**：每个页面用同一个状态面板包裹数据区（加载=骨架条、错误=说明+动作、空=图标+标题+主按钮），不允许某页出现裸白屏。
- **可访问性**：开关是 `role="switch"` + `aria-checked`；焦点环为 4px 墨黑 outline + 2px offset；装饰性图标 `aria-hidden`。

### 视觉契约

颜色、间距、边框、阴影一律取 `design.md` 的 token；`docs/design/goclash-ui-reference.html` 是像素级对照物，实现时逐屏比对。硬阴影不参与布局（用 `box-shadow`，不用位移占位），旋转只出现在主行动按钮与状态 Hero 上。

## Testing Decisions

- **单一 seam**：`App` 接受一个 `gateway` 参数。测试只挂载 `<App gateway={mockGateway} />`，通过点击与断言驱动，不单独为每个页面建测试夹具，也不测内部组件树结构。
- **什么算好测试**：只断言用户可见的结果——页面上出现什么文字、哪个元素带选中态、mock 收到哪个调用。不断言类名、不断言子组件层级、不测实现细节。
- **纯函数例外**：`format` 里的字节/速率/延迟分级是纯函数，直接单测，不需要 seam。
- **mock 是受控的**：测试用例可以切换 mock 模式（正常 / 空 / 报错 / 挂起），用来验证三种状态面板。
- **先例**：仓库目前没有任何测试。工具链由 01 号票建立（Vitest + Testing Library + jsdom），并接进 CI；后续每张票至少新增一条走 seam 的用例。
- **不做的测试**：视觉回归（像素快照）、Go 侧单测（本期没有 Go 改动）。

## Out of Scope

- 真实 mihomo 接入：REST `/proxies`、`/connections`、`/traffic`、WS `/logs` 的读写，以及内核进程管理。
- 系统代理写入、TUN 启停、系统服务安装（macOS 授权弹窗那一套）。
- 托盘图标与托盘浮窗（需要第二个 Wails 窗口 + 托盘菜单，单独一版）。
- 深色主题：设计稿只给了 light；深色需要另一套边框/阴影反转规则。
- 多语言：界面文案先写死中文。
- 订阅导入的真实网络请求与解析（YAML 解析在 Go 侧）。
- 应用自动更新。

## Further Notes

- 设计稿里存在两组「红绿灯」问题（原生 vs 假点），已在窗口决策中定案；实现时以原生为准。
- 首页流量图不引图表库，用 SVG 手绘即可：60 个采样点、面积填充 + 折线 + 黑色基线，避免为一个图引入 40KB 依赖。
- 字体决策与设计稿的「Inter 唯一」有偏差，属于中文兼容的必要偏离，已记录在决策里；若将来要上 Windows/Linux，中文字体栈需要再评估一次。
- 托盘浮窗画板（03）暂不落地，但它的结构（状态 + 模式 + 4 节点 + 流量 + 主按钮）与本 spec 的首页/代理页共享组件，将来复用成本很低。
