# Welcome to Your New Wails3 Project!

Congratulations on generating your Wails3 application! This README will guide you through the next steps to get your project up and running.

## Tooling & Workflow

This repo ships with a full tooling setup (git hooks, linting, formatting, CI).

### Git hooks (husky)

| Hook         | What it does                                                 |
| ------------ | ------------------------------------------------------------ |
| `pre-commit` | Runs `lint-staged` (eslint + prettier on staged files)       |
| `commit-msg` | Validates the message with commitlint (Conventional Commits) |

Commit messages must follow [Conventional Commits](https://www.conventionalcommits.org/), e.g.:

```
feat: add proxy group switching
fix(ui): correct tray icon on macOS
chore: update wails to v3.0.0
```

Allowed types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.

### Scripts

| Command                | Description                                     |
| ---------------------- | ----------------------------------------------- |
| `npm run lint`         | ESLint over the repo (frontend TS/TSX)          |
| `npm run lint:fix`     | ESLint with auto-fix                            |
| `npm run format`       | Prettier, write mode                            |
| `npm run format:check` | Prettier, CI check mode                         |
| `npm run typecheck`    | `tsc --noEmit` against `frontend/tsconfig.json` |
| `npm run check`        | format:check + lint + typecheck                 |

Go code is checked with `gofmt`, `go vet` and `golangci-lint` (config in `.golangci.yml`).

### CI (GitHub Actions)

`.github/workflows/ci.yml` runs on pushes/PRs to `main`:

- **Frontend** — prettier, eslint, `tsc` typecheck
- **Go** — gofmt, `go vet`, golangci-lint, compile check (with Linux GTK/WebKit deps)
- **Build (macOS)** — full frontend + backend build, uploads the binary as an artifact
- **Commitlint** — PR commit messages are validated in CI as well

### Notes

- `frontend/bindings/` is generated by Wails3 — it is excluded from prettier/eslint and should not be edited by hand.
- `frontend/dist/` is generated at build time (gitignored), but `main.go` embeds it via `go:embed`, so the directory must exist before `go build`.
- The Go module is still named `changeme` from the template — rename it in `go.mod` (and `.golangci.yml` goimports prefix) when you pick a final name.

## Getting Started

1. Navigate to your project directory in the terminal.

2. To run your application in development mode, use the following command:

   ```
   wails3 dev
   ```

   This will start your application and enable hot-reloading for both frontend and backend changes.

3. To build your application for production, use:

   ```
   wails3 build
   ```

   This will create a production-ready executable in the `build` directory.

## Exploring Wails3 Features

Now that you have your project set up, it's time to explore the features that Wails3 offers:

1. **Check out the examples**: The best way to learn is by example. Visit the `examples` directory in the `v3/examples` directory to see various sample applications.

2. **Run an example**: To run any of the examples, navigate to the example's directory and use:

   ```
   go run .
   ```

   Note: Some examples may be under development during the alpha phase.

3. **Explore the documentation**: Visit the [Wails3 documentation](https://v3.wails.io/) for in-depth guides and API references.

4. **Join the community**: Have questions or want to share your progress? Join the [Wails Discord](https://discord.gg/JDdSxwjhGf) or visit the [Wails discussions on GitHub](https://github.com/wailsapp/wails/discussions).

## Project Structure

Take a moment to familiarize yourself with your project structure:

- `frontend/`: Contains your frontend code (HTML, CSS, JavaScript/TypeScript)
- `main.go`: The entry point of your Go backend
- `app.go`: Define your application structure and methods here
- `wails.json`: Configuration file for your Wails project

## Next Steps

1. Modify the frontend in the `frontend/` directory to create your desired UI.
2. Add backend functionality in `main.go`.
3. Use `wails3 dev` to see your changes in real-time.
4. When ready, build your application with `wails3 build`.

## Development

### Prerequisites

| Tool    | Version  | Notes                                                       |
| ------- | -------- | ----------------------------------------------------------- |
| Go      | 1.26+    | see `go.mod`                                                |
| Node.js | 20+ (22) | see `.nvmrc`                                                |
| Wails3  | v3.0.0   | `go install github.com/wailsapp/wails/v3/cmd/wails3@latest` |
| Task    | v3       | `go install github.com/go-task/task/v3/cmd/task@latest`     |

### Common commands

```bash
npm install            # install lint/format tooling (also installs git hooks)
npm ci --prefix frontend

npm run format         # Prettier write
npm run format:check   # Prettier check  (CI)
npm run lint           # ESLint         (CI)
npm run lint:fix       # ESLint --fix
npm run typecheck      # tsc --noEmit   (CI)
npm run check          # all of the above checks

task lint              # Go + frontend checks
task format            # gofmt + Prettier
task dev               # wails3 dev
```

### Code style

- TypeScript / TSX / JSON / YAML / Markdown: Prettier (`.prettierrc.json`)
- TypeScript / TSX: ESLint flat config (`eslint.config.mjs`), includes React Hooks and React Refresh rules
- Go: `gofmt` + `golangci-lint` (`.golangci.yml`)

### Commit convention

Commits follow [Conventional Commits](https://www.conventionalcommits.org/) and are validated by
commitlint through a Husky `commit-msg` hook:

```
feat: add clash profile importer
fix(ui): prevent window flicker on startup
chore(ci): cache npm dependencies
```

Allowed types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`,
`revert`.

Staged files are formatted and linted automatically before each commit (`lint-staged`).

### Continuous integration

| Workflow                           | Trigger             | What it does                                                     |
| ---------------------------------- | ------------------- | ---------------------------------------------------------------- |
| `.github/workflows/ci.yml`         | push / PR to `main` | Prettier, ESLint, tsc, gofmt, go vet, golangci-lint, macOS build |
| `.github/workflows/commitlint.yml` | pull request        | Validates commit messages and the PR title                       |
| `.github/workflows/release.yml`    | tag `v*` or manual  | Builds macOS/Linux/Windows binaries into a draft release         |
